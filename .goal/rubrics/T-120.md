# Rubric — T-120: Bench scorecard

Graded by `/outcome-grader` (or the checker, acting as a fresh stateless judge) against
`scripts/bench_trial.py`'s real, cited run output — not a description of what it would do.

## Criteria

1. **A real seeded corpus with a genuine, verifiable defect.** `BenchCorpus.seeded_bugs`
   describes a real broken build (reuses the T-110-style fixture regression), not a placeholder
   bug. Verify: the corpus JSON under `projects/regression-demo/bench/` cites a real `location`
   and `detect_hint`.
2. **A real AutoTester trial.** The pipeline (`execute.py` + `grade.py`) runs for real against the
   broken fixture, through a real non-mock judge (`grader_provider` names a real vendor, e.g.
   `gemini`). Findings are derived mechanically from the resulting `Verdict`s, not hand-typed.
3. **Scoring goes through `BenchTrial.score`, never hand-computed.** `stages/bench.py::scorecard`
   calls `trial.score(corpus)` — grep the calling code and the manifest for any parallel
   hand-computed detection-rate arithmetic; there must be none.
4. **The scorecard names both participants side by side** (AutoTester's real trial and a
   documented human-oracle baseline) — the comparison the north star asks for.
5. **Honest labeling.** The human side is explicitly labeled as an oracle baseline (not a live
   timed trial) in the contract, the manifest, and the run script's own output — no claim of a
   real human tester's involvement that didn't happen.

## No-fire

- Whether the "human" baseline reflects real human timing or behavior — it is declared a
  baseline, not a live trial, by design (no tester was available this cycle).
- Multi-corpus or leaderboard-style benchmarking — one real corpus is the bar.

## Satisfied when

All 5 criteria are met on cited evidence — the real run's console output, the real Verdict/Finding
JSON files, and the scorecard's own printed numbers (traceable to `BenchTrial.score`, not to any
hand-typed value in the script).
