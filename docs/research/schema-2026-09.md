## 2. Gaps to close before P2 ingest locks FlowSpec

Ordered by cost-of-changing-later. Each names the motivating source.

1. **`Action` enum is missing `HOVER`, `PRESS_KEY`, `SCROLL`** — Mind2Web's four ops include Hover; Midscene has `aiHover`/`aiScroll`/`aiKeyboardPress`. Ingest from video will see hover-menus and Enter-to-submit on day one; an enum gap becomes a lossy transcription. Add now (enums.py, `Action`).
2. **`ExpectedState` has no `answer` / extracted-value slot** — WebArena `reference_answers{exact_match,must_include,fuzzy_match}`, Online-Mind2Web `agent_final_answer`, Midscene `aiQuery`. Without it BenchTrial cannot replay a WebArena task. Add `ExpectedState.answer: AnswerMatch | None` with `{exact: str|None, must_include: list[str], fuzzy: str|None}`.
3. **`ExpectedState.url` needs a match mode** — WebArena `url_note` (default "GOLD in PRED"); our field says "exact URL or glob" but no flag. Add `url_match: Literal["exact","contains","glob"] = "contains"`.
4. **`visible_text`/`dom_asserts` have no per-URL scoping** — WebArena `program_html[]{url,locator,required_contents}` asserts on a *different* page than the last step (e.g. check the admin list after a submit). Add optional `ExpectedState.checks: list[PageCheck{url|"last", locator, must_include[], exact}]` OR accept limitation and note it. Recommend: add — it is the only way to express "side effect on another screen".
5. **`Case` has no `dimension` beyond `CaseClass`** — WTB scores against Functionality/Constraint/Interaction/Content. Our 15 classes map cleanly (INPUT_* → Constraint, DOUBLE_SUBMIT/BACK_REFRESH/CONCURRENT_TAB → Interaction, HAPPY → Functionality, LOCALE/VIEWPORT → Content). Do **not** add a field; add a `DIMENSION_BY_CLASS` map in enums.py next to `KIND_BY_CLASS` so the WTB adapter is a lookup, not a judgment.
6. **`Case.tags: list[str]`** — Gherkin `@tags`, CTRF `tags[]`, Allure `tag` label. Free-form, non-taxonomic (e.g. `@smoke`, `@wip`, `@needs-video`). `CaseClass` is closed and must stay closed; tags are the escape valve so nobody widens the taxonomy to fit a one-off.
7. **`Flow` has no `seed` / `Background`** — Playwright agents `// seed:` and Gherkin `Background` both separate "get to the starting state" from the scenario. `preconditions: list[str]` is prose only. Add `Flow.setup_flow_id: str | None` (a Flow whose steps run first). Cheap, makes `requires_auth` a special case of setup.
8. **`RawResult` lacks `started_at`/`finished_at` and `attempt`** — CTRF requires `start`/`stop` ms and models `retries`/`retryAttempts`/`flaky`; we keep only `duration_s` + `iterations`. Add `started_at`, `finished_at: datetime | None`, `attempt: int = 1`. Needed for CTRF export and for flaky detection (`Script.stable_runs` tracks the script, not the case).
9. **`RawResult` lacks `browser`/`viewport`** — CTRF `browser`/`device`; our `VIEWPORT_MOBILE` class runs under a different viewport and the result does not record which. Add `browser: str | None`, `viewport: str | None`.
10. **`Evidence` lacks `content_type`** — CTRF attachments require `contentType`; Allure requires `type`. `EvidenceKind` implies it but a tool reader cannot infer `image/png` vs `image/jpeg` vs `application/zip` (trace). Add `content_type: str | None`.
11. **`Verdict` has no `known`/`muted` flag** — Allure `statusDetails{known,muted}`: a FAIL that matches an already-filed bug should not re-alert. Add `Verdict.known_issue_ref: str | None`. Motivated also by Bench false-positive accounting (a re-report of a known bug is not a new finding).
12. **`Case` stable id vs execution id** — CTRF identity model (`testId` stable, `executionId` per run). Ours is right (content id + `Run.id`) but `Verdict` should carry `case_fingerprint` = the Case id *at grade time* so a regenerated case with a new id can still be joined to history. Rename nothing; add `Verdict.rubric_hash` already exists — add `Verdict.case_hash` symmetrically.
13. **`FlowSpec` lacks `app_overview: str`** — Playwright planner's `## Application Overview` section; also what a human reviewer reads first. One free-text field; ingest already derives it.

Not gaps (checked, ours already covers): Provenance (`SourceRef` beats every surveyed format); separate `RawResult` vs `Verdict` (nobody else separates observation from judgement — keep); `Rubric.no_fire` (no equivalent anywhere; WTB's false-positive metric is exactly what it prevents).

## 3. Deliberate divergences — keep

- **Observation ≠ judgement.** Every surveyed result format collapses to one `status`. Ours splits `Outcome{completed,errored,blocked_hitl}` from `Result{PASS,FAIL,BLOCKED,INCONCLUSIVE}`. WebJudge (Online-Mind2Web) is the only peer that grades from evidence after the fact, and it reports 87% human agreement — the design we are betting on. Keep; export collapses to CTRF `status` at the adapter, never in the model.
- **Closed `CaseClass` taxonomy** vs free tags/headings everywhere else. The 1-per-class-per-flow guarantee is the product differentiator (WTB's headline finding is "insufficient test completeness"). Keep closed; add `tags` for the free-form need (gap 6).
- **`ExpectedState.visual_signal` as first-class** — only Midscene `aiAssert`/Momentic `assert:` treat NL assertions as primary. We keep it *alongside* structured asserts, not instead of them; the grader cites evidence for structured ones and uses vision for the NL one. Keep.
- **`SourceRef` per step** — no format has it. It is the entire "watch the second the system learned this" review story. Keep, and never make it optional in ingest output (it is `| None` in the schema for hand-written cases only).
- **Content-addressed Case id** — CTRF `testId` is "stable across runs" but tool-defined; ours is derived from meaning, which is stronger. Keep.
- **`Rubric.no_fire`** — nobody else has it. Keep.
- **No `Scenario Outline`/`Examples` in-model.** Parametrised cases are expanded to N concrete Cases at EXPAND time (content-addressed, so no duplication). Gherkin export can *fold* sibling cases back into an Outline. Keep; document in the adapter.
- **`extra="forbid"`** vs CTRF's `extra{}` extensibility. Keep forbid; the CTRF adapter emits `extra` on the way out.

## 4. Interop adapters worth having (each ≤ 1 module, under `autotester/interop/`)

| Adapter | Direction | Why | Mapping notes |
|---|---|---|---|
| Case → Playwright spec `.md` | export | EXPAND already targets this; feeds `generator`/`healer` unchanged | Flow → `## N. <name>`, Case → `### N.M <title>`, steps → numbered list, `ExpectedState` → `**Expected Results**` bullets, `Flow.setup_flow_id` → `// seed:` |
| Case → Gherkin `.feature` | export | human/PM readable; `CaseClass` → `@class:input_boundary`, `Severity` → `@S1` | preconditions → `Given`, non-assert steps → `When`, `ExpectedState` → `Then`; siblings differing only in `value` → `Scenario Outline` + `Examples` |
| Verdict+RawResult → CTRF JSON | export | CI dashboards, GitHub summary, any CTRF reporter | `PASS→passed, FAIL→failed, BLOCKED→skipped, INCONCLUSIVE→other`; `rawStatus` = our `Result`; `ai` = scoreboard + failures; `testId` = case id; `executionId` = run id + case id; `attachments` from `Evidence`; `labels{case_class,severity,flow_id}` |
| Verdict → Allure result JSON | export (optional) | Allure history/flaky view | `historyId` = case id; `severity` label; `statusDetails.known` from gap 11 |
| WebArena task JSON → Case + Rubric | import | run WebArena/Mind2Web tasks through our executor+grader for calibration | `intent` → title, `start_url` → first NAVIGATE step, `eval` → `ExpectedState.answer/url_match/checks` (gaps 2–4), `require_login` → `requires_auth` |
| Online-Mind2Web result.json ← Run | export | submit our agent to WebJudge; free external grader calibration | `action_history[]` from step Evidence (screenshot+url per step), `agent_final_answer` from extracted answer |
| WebTestBench checklist ← Case | export | measure our EXPAND coverage against gold `{d,a,e}` | `d` = title, `a` = steps joined, `e` = ExpectedState prose; dimension via `DIMENSION_BY_CLASS` |
| Midscene / Momentic YAML ← Case | export (later) | alternative executor backends | `aiTap/aiInput/aiAssert`; `visual_signal` → `aiAssert` verbatim |

```
## D-005 (proposed; D-004 is taken) — FlowSpec/Case schema: confirm with 13 amendments before P2 ingest lock
Date: 2026-09-03   Status: PROPOSED   Approver: Umesh   Task: T-004

Decision: CONFIRM the five-artifact model (FlowSpec / Case / RawResult / Verdict + Rubric) and the
observation≠judgement split. AMEND before P2 with the additions in .work/schema-2026-09.md §2:
  enums.Action += HOVER, PRESS_KEY, SCROLL                          (Mind2Web ops, Midscene)
  ExpectedState += answer{exact,must_include,fuzzy}, url_match,
                   checks[]{url,locator,must_include,exact}          (WebArena eval spec)
  Case += tags[]; enums += DIMENSION_BY_CLASS                        (Gherkin/CTRF tags; WebTestBench)
  Flow += setup_flow_id                                              (Playwright seed, Gherkin Background)
  FlowSpec += app_overview                                           (Playwright planner spec)
  RawResult += started_at, finished_at, attempt, browser, viewport   (CTRF required fields)
  Evidence += content_type                                           (CTRF/Allure attachments)
  Verdict += known_issue_ref, case_hash                              (Allure statusDetails.known; CTRF identity)
No renames. No removals. CaseClass stays closed. extra="forbid" stays.

Reasoning: surveyed six format families. None separates executor observation from grader judgement
(we do — WebJudge is the closest peer at 87% human agreement); none carries per-step source
provenance (we do). Our gaps are all at the edges — action vocabulary, answer-style assertions,
timing/attempt fields, and free tags — and every one is additive. Adding them now is a field each;
adding them after ingest has produced FlowSpecs means a migration plus re-review of every spec.

Rejected: (a) Scenario Outline in-model — expand to concrete Cases instead, fold back on export.
(b) collapsing Outcome+Result into one CTRF-style status — loses the independent-grader guarantee.
(c) making CaseClass open — the completeness guarantee is the product.

Verification: `uv run pytest -q` + `uv run autotester doctor` green after amendments; adapters
Case→Gherkin and Verdict→CTRF round-trip on the fixture suite (T-0xx).
```
