**Contract:** `qa/contracts/core-invariants.md` (C2, C3, C7); no feature contract owns `tooling`

## What was wrong

`qa/.last-tick` jumps `2026-09-11T09:22:41Z` straight to `2026-09-16T05:45` — 4.85 days — with 94
open ledger rows, 20 pending goal tasks, a `ready-for-check` manifest, and **no `qa/.paused`**. The
`ScheduleWakeup` chain did not survive, zero goal tasks moved, and
`qa/gates/t162-contract-approval.md` sat unanswered for five days.

The outage was found by a sweep grepping timestamps out of a prose log by hand. That is the actual
defect this unit addresses: there was **no instrument**. The session-start hook does print the last
tick's age, but it prints it when a session opens, and the shape of this outage was that no session
opened.

## What this unit refuses to claim, up front

**It does not keep the loop alive, and nothing in this repo can.** Nothing here runs while the app
is closed — the maker skill says so itself. A "heartbeat" that cannot fire during the outage it is
meant to catch would be a guard that cannot fail, which is AT-218, the repo's own top systemic risk.
So this unit makes the silence **legible afterwards** instead: gaps enumerated, measured, and
classified, so "the loop slept" becomes a number the repo can state rather than something a person
happens to notice.

AT-368's `expected` offers two paths — "a heartbeat whose failure is itself visible, **or** an
explicit `qa/.paused` so a deliberate stop is distinguishable from a dead loop". This is the second,
plus the measurement that makes the first checkable by a human or a sweep.

## The disclosure this tool carries

`/maker pause` writes `qa/.paused`; `/maker resume` **deletes** it. A finished pause therefore
leaves no trace on disk, so a closed gap can never be proven deliberate and every historical gap
reads as `SLEEP` whether it was one or not. The tool says this out loud rather than letting a
reader take six `SLEEP` rows at face value. Fixing it properly means making resume append a durable
line — a change to the maker skill, which lives **outside this bound root**, so it is disclosed
here rather than papered over.

### Row 4 is here because my first version of it was vacuous, and sabotage caught it

The first sabotage pass ran four mutations and **mutation D survived**: dropping `.astimezone(UTC)`
left all 14 tests green. My test claimed normalisation protected the *measurement* and asserted a
30-minute delta across two offsets — but `datetime.fromisoformat` already returns aware datetimes,
and Python subtracts those correctly across offsets, so that assertion held with or without the
code it claimed to cover. A green sabotage meaning "this test proves nothing" is precisely AT-218's
class, and the C7 INCONCLUSIVE rule is the only reason it surfaced.

The claim was wrong, not the code. `.astimezone(UTC)` is load-bearing for **reading**, not
arithmetic: a report mixing `+00:00` and `+05:30` rows makes a human do offset arithmetic to see
which outage was longer, which is how a 5-day gap gets skimmed past. I rewrote the docstring to stop
overclaiming and added the test that isolates the real property, then **rebuilt the extract from
scratch and re-ran all four mutations** against the corrected file. Only the second run is reported
in the table above.
