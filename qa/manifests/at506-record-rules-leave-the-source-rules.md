## The measurement first


So the file was one ordinary unit away from failing the rule it exists to enforce, with no warning
on the way. That is the erosion signal; it is not by itself a reason to split.

**The reason to split is that the seam is real, not arithmetic.** The two halves read different
trees and answer different questions:

| | reads | asks |
|---|---|---|
| source rules | `src/`, `tests/` | did the code stay readable? |
| record rules | `docs/FEATURES.jsonl`, `qa/` | did the project's account of itself stay true? |

Splitting on a line count alone would have been drift with a cap for an excuse. All three units
that pushed the file over landed in the record half, which is the same evidence for both claims.

## What changed

- **New `src/autotester/ledger/checks.py`** (105 lines) — `check_ledger`, `check_qa_issue_rows`,
  `_passed`, `ISSUE_ID`, `_MARKER_LEAD`, `_is_marker_line`, moved verbatim. It lives inside the
  existing `ledger` package rather than becoming a new top-level concept.
- `src/autotester/doctor.py` (287 -> 204) keeps `Violation`, `run()`, and the source rules.
  `run()` imports the two record checks **function-locally** — the idiom this file already used for
  `ledger.render` and `ledger.store` — so `checks.py` can import `Violation` from `doctor` with no
  cycle. The now-unused module-level `import re` is dropped.
- `tests/test_doctor.py` (282 -> 133) and **new `tests/test_ledger_checks.py`** (165): the tests
  followed their module, along the same seam.
- `tests/test_ledger.py` — one reference updated (`doctor.check_ledger` -> `checks.check_ledger`).
- `docs/ARCHITECTURE.md` — the concept-to-file map row for design enforcement, authorized by D-026,
  so it no longer names `doctor.py` as the home of ledger validity.
- `docs/MAP.md`, `docs/SNAPSHOT.md` — regenerated by `autotester map` / `autotester snapshot`, never
  hand-edited.

## Known limits (disclosed, not claimed)

- **Three closed units' evidence files no longer run, and I did not rewrite them.** `at496`,
  `at500` and `at504` all anchor their mutations at `src/autotester/doctor.py`, where those lines no
  longer are. Measured, not assumed:

  ```
  $ uv run python scripts/mutation_check.py qa/evidence/at504-.../mutations.json
  MUTATION RUN INVALID: … names test(s) that are not collected: [...]   exit 2
  ```

  It **refuses loudly** rather than reporting a false result — the instrument's fail-closed design
  working exactly as intended. I left those files alone on purpose: they record what was verified at
  the commit where it was verified, and editing a closed unit's evidence to keep it green is how
  evidence stops meaning anything. The cost is real, though: a checker re-verifying an older unit
  hits a refusal that looks like a defect until it reads this note. **If the checker judges that
  cost higher than the principle, say so in the verdict** — that is a fair call to overrule me on,
  and it is better made now than discovered in six weeks.
- **`docs/ARCHITECTURE.md` is now exactly 150 lines against its 150-line cap.** My first edit made
  it two rows and tipped it to 151; it is one row now. The next row anyone adds to that table breaks
  the build. Not this unit's to fix, but nobody should meet it by surprise.
- **D-026 does not enumerate `docs/SNAPSHOT.md`** in `Changes-authorized`, only `docs/MAP.md`. Both
  are tool-regenerated rather than hand-edited, and `doctor` demanded the snapshot regeneration
  after the new module appeared. I judged that regenerating a generated file is not a prose change
  needing authorization, and am flagging the judgement rather than burying it.
- **`AT-488` and `AT-502` are untouched.** `scripts/mutation_check.py` is still 416 lines and
  `scripts/` sits outside C2's literal `src/`+`tests/` scope, so `doctor` cannot see it at all.
  This unit fixes one file, not the class.
- **The fingerprint proves the two record checks are unchanged, not the whole of `doctor`.** The
  source rules were not moved and are covered by `tests/test_doctor.py`'s untouched 133 lines, but
  the byte-identical claim is specifically about `check_qa_issue_rows` and `check_ledger`.
