## Cycle 2 — fix for verdict `qa/verdicts/t100-ui.md` (Cycle checked: 1, FAIL — U5)

- **AT-035** (high): `project_detail` (`app.py:80-81`) interpolated the raw, unescaped `slug`
  path parameter into two `href='/projects/{slug}/...'` attributes, while every other value in
  the same function correctly went through `escape()`. The checker reproduced it live: a project
  directory named `demo' onmouseover='alert(1)` made `GET /projects/<that slug>` return the
  injected attribute unescaped.
  **Fixed:** `project_detail` now computes `safe_slug = escape(slug)` once and uses it in both
  `href` attributes — the only two places `slug` was rendered into HTML at all (grepped the
  whole file: every other `{slug}` usage is either an `HTTPException` detail, which FastAPI
  serializes as JSON, never HTML, or a `RedirectResponse` Location header, not page content).
  **Re-verified with the checker's own reproduction, not a weaker substitute**: added
  `test_project_detail_escapes_the_slug_in_its_own_links`, seeding a project directory named
  `demo' onmouseover='alert(1)` (same payload) and asserting the response contains the
  HTML-entity-encoded quote (`&#x27;`/`&#39;`) rather than a raw `'` that could close the `href`
  attribute early.

- `src/autotester/ui/env_editor.py` (new, ~40 lines) — `set_env_value(env_path, key, value)`: the
  one legitimate write path to the repo-root `.env`. Replaces an existing `KEY=` line or appends
  a new one; preserves every other line untouched; never returns, logs, or echoes `value`.
  **Post-dispatch fix**: an automated security review (mid-cycle, after the checker was first
  dispatched) correctly flagged the initial version as writing `.env` with default/inherited file
  permissions instead of owner-only — a credential file readable by other local users/processes
  defeats the point of the boundary before a value ever reaches `SecretStore`. Fixed to write via
  `os.open(..., 0o600)` + a defensive `os.chmod(..., 0o600)` after write (covers the case where an
  existing file had wider permissions already). `os.chmod` only toggles the read-only flag on
  Windows (no POSIX group/other bits there), so this is a real restriction on POSIX deployments
  and a harmless no-op on this Windows dev box — pinned by a new POSIX-only test
  (`test_set_env_value_writes_owner_only_permissions`, skipped on Windows via
  `@pytest.mark.skipif(os.name == "nt", ...)`, so it stays honest about what it can actually prove
  in this environment). 10 tests in `test_ui.py` now, not 9.
- `src/autotester/ui/app.py` (new, 128 lines) — FastAPI app: `GET /` (project list), `GET`/`POST
  /onboard` (creates a `Project` via `ProjectStore.save_project`), `GET /projects/{slug}` (review

## Scope notes for the checker

- Per the no-fire list: no auth, no HTMX/JS, no live-polling run view (point-in-time snapshot
  per request), no run/ingest triggering from the UI, no CSRF protection — all explicitly
  deferred, matching the plan's own v1 scope and this contract's stated boundaries.
- The env editor's `<input type='password'>` masks the field visually in a browser, but the
  actual security guarantee is server-side (U3: the value is never rendered/echoed in the HTML
  response at all, checked by the test asserting the real value string is absent from the
  response body) — the password input type is a UX nicety, not the safety mechanism.
- No secrets touched by this unit's own code paths in tests — `set_env_value` is exercised with
  fake test values only (`"new-real-value"`, `"s3cr3t-real-value"` — fixture strings, never a
  real `.env` credential).

## Cycle 2 — checked-PASS, then two more post-PASS security fixes

Verdict: `qa/verdicts/t100-ui.md` (Cycle checked: 2, PASS, 5/5; AT-035 fixed). Goal task T-100
closed by the checker.

**Two more automated-security-review findings landed after that PASS**, both HIGH severity, both
on the same credential-adjacent surface this contract already scrutinizes under U3:
1. **Newline injection into `.env`** (`ui/env_editor.py`) — a value containing `\n`/`\r` could
   smuggle a second, attacker-chosen `KEY=VALUE` line into the credential file. Fixed:
   `set_env_value` now refuses (`InvalidEnvValue`) a `key` that isn't `UPPER_SNAKE_CASE` or a
   `value` containing a newline/carriage-return, before ever touching the file. The route
   (`env_editor_submit`) catches `InvalidEnvValue` and returns 400.
2. **Unvalidated `slug` used directly as a filesystem path** (`ui/app.py`) — every route/form
   that takes `slug` handed it straight to `ProjectStore(slug)`/`ProjectPaths(slug)`, which builds
   `root/projects/<slug>` with no validation; same root cause as AT-035, one contract's worth
   deeper. Fixed: `_require_slug` (same pattern as `schema.project.Project.slug`'s own field
   validator, `^[a-z][a-z0-9-]*$`) now gates `_load_project_or_404` (covers every `GET`/`POST`
   route keyed on `slug`) and `onboard_submit` (before a new project is ever created). Added
   `_require_safe_id` for `run_id` too (`store.load_verdicts(run_id)`/`load_results(run_id)` build
   a path from it the same way) — same class of risk, same fix shape.

Both fixes are additive input validation, not a change to what any route already-correctly-tested
does on valid input — re-ran the full suite, ruff, and doctor clean (`uv run pytest -q` → 191
collected, up from 188; `uv run ruff check src tests scripts` → clean; `uv run autotester doctor`
→ clean). 6 new/rewritten tests in `tests/test_ui.py`: a malicious slug is now rejected outright
(400) rather than merely escaped; `_require_slug` rejects `..`, path separators, empty, uppercase,
and a leading-hyphen slug (tested directly against the function, since a literal `..` path segment
normalizes away client-side before reaching the server — confirmed empirically, documented in the
test); `onboard_submit` refuses an invalid slug; a newline-carrying `.env` value is refused and
never reaches disk.

Dispatching one more confirming checker pass for these two post-PASS fixes specifically (not a new
fix cycle against a FAIL — T-100 already PASSed; this is the same "extra scrutiny on
credential-adjacent code" discipline this project has applied to every prior security finding).
