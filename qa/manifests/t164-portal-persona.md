## What changed

New durable, cross-run product model promoted from per-crawl knowledge, per D-038 (an artifact + a
stage, NOT a new pipeline stage and NOT a new datastore).

- `src/autotester/schema/portal_persona.py` (NEW) — `PortalPersona(Artifact)` (`extra="forbid"`) with
  `profile`, `auth` (SHAPE only), `screens`, `transitions`, `taught_flows`, `gotchas`,
  `screenshot_refs`, and `history: list[PersonaRevision]`. Supporting models: `PersonaProfile`,
  `AuthField`, `AuthShape`, `PersonaScreen`, `PersonaTransition`, `FlowRunRef`, `TaughtFlow`, `Gotcha`,
  `PersonaRevision` (blank-summary validator). `PortalPersona.resolve_run(FlowRunRef)` resolves a Quick
  Re-Run pointer back to its flow (PP6).
- `src/autotester/stages/portal_persona.py` (NEW) — `build_portal_persona(store, *, crawl_id=None,
  redactor=None) -> PortalPersona`: builds an incoming persona from the reviewed FlowSpec + a crawl's
  screen graph, MERGES it into the existing persona (PP2), appends a dated `PersonaRevision` iff
  something changed (PP3), scrubs every string through the project `Redactor` and refuses to persist
  while a raw secret survives (PP5), persists `projects/<slug>/portal_persona.json` via the filestore,
  and regenerates `knowledge.md` (PP4). **Naming note:** the contract sketches the entry as
  `run(input, ctx)`; it is named `build_portal_persona(store, ...)` because a public top-level `run`
  already exists in `src/autotester/doctor.py`, and C3 / `check_duplicate_definitions` forbids a second
  — this follows the repo's `build_screen_map(store)` convention. No behaviour difference from the
  contract sketch (`store` is the `ctx`; the FlowSpec + crawl id are the `input`).
- `src/autotester/stages/portal_persona_view.py` (NEW) — `render_knowledge(persona) -> str`, the
  `knowledge.md` view projected entirely from the persona JSON (PP4). Split from the stage to keep both
  files well under 300 lines.
- `src/autotester/core/paths.py` (EDIT in place) — added `ProjectPaths.portal_persona` property
  (`projects/<slug>/portal_persona.json`).
- `src/autotester/store/project_store.py` (EDIT in place) — added `save_portal_persona` /
  `load_portal_persona` (thin filestore wrappers; no new store — reuses D-036 filestore precedent).
- `tests/test_portal_persona.py` (NEW) — one offline test per PP1-PP6 (7 tests; PP3 has two: delta +
  identical-rerun). Uses `ProjectStore(slug, tmp_path)`, so the real repo tree is never touched.
- `docs/MAP.md`, `docs/SNAPSHOT.md` (regenerated by `autotester map` + `autotester snapshot`; no
  ARCHITECTURE prose change, per D-038).
