## Methodology note for consolidation (not a ledger finding)

A first automated pass for "verdict PASS but manifest not checked-PASS" (part of check 1's
pair-state reconciliation) produced 136 false positives, then 16, then 3, purely from a
regex that (a) only matched `## Status:` headings and missed the equally common inline
`**Status:** checked-PASS (...)` convention, and (b) took the *first* `Status:` match in a file
instead of the *last* — several older multi-cycle manifests (e.g. `at230-gemini-schema.md`,
`t133-ensemble-and-issues.md`) legitimately carry a cycle-1 `## Status: superseded by cycle 2`
line followed by a later `## Status: checked-PASS (cycle 2 ...)` line. After correcting for both,
all 136 PASS-verdict/manifest pairs on disk resolve to a genuine terminal PASS (including
`at015-at028-hook-adapter-fix.md`'s stall-recovery PASS, which never emits a `checked-PASS`
literal but whose verdict says `VERDICT: PASS (stall recovery confirmed)` with matching cycle 4).
**Zero genuine PASS-not-closed-out findings.** Recording this so no later sweep repeats the same
regex mistake and re-reports a false 136-item backlog.
