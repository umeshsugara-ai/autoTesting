## Instrument caveats, stated because this sweep is largely about them

Three of my own scanners were wrong in the way C12 describes, and I found it by being corrected
rather than by checking:

- `Status:\s*(.+)` cannot match `## Status (cycle 2):` — the parenthetical sits between the word and
  the colon. It reported a file with two status headings as having none.
- `^VERDICT:` first-match reads a multi-cycle verdict file as its **earliest** cycle. This is the one
  that can fabricate a FAIL: a cycle-3 PASS reads as a cycle-1 FAIL, the direction that stalls a
  closed unit forever. The maker asked for it to be singled out and it is singled out here.
- `Cycle checked:\s*(\S+)` captured markdown bold markers instead of numbers.

And one misattribution reached the peer: I inferred the hook's `PASS not closed out: 1` from a
predicate that was **not** the hook's predicate. The count is `t182`, permanently, and never was
`at575`. All of this is on AT-662 against the checker. C12 now carries the maker's rule that would
have prevented it: *a matcher reports on the state its pattern can express*, so verifying by
construction is only half a rule — the construction has to be the same one the claim is about.
