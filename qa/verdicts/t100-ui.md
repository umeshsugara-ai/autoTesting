## U5 — every user-derived string is HTML-escaped — **FAIL**

The contract's own instruction was to read `ui/app.py` in full and look for any spot that might
have been missed, not just re-run one payload. Doing exactly that surfaced a real miss:

`project_detail` (app.py:80-81) builds two links using the **raw, unescaped** `slug` path
parameter:

```python
f"<a href='/projects/{slug}/env'>credentials</a> | "
f"<a href='/projects/{slug}/report'>report</a>"
```

Every other value in the same function (`project.name`, `review`) is wrapped in `escape(...)` —
these two are not. This is not theoretical: `_load_project_or_404` resolves the project via
`ProjectStore(slug)`, which uses the **raw URL-supplied string** as the literal directory-lookup
key — not the project's own schema-validated `Project.slug` field (which is pattern-constrained
to `^[a-z][a-z0-9-]*$` only at `/onboard`-time, and only for that field, not for the directory
name `ProjectStore` is constructed with). I reproduced this live this cycle: seeded a project
directory via `ProjectStore("demo' onmouseover='alert(1)", root).save_project(...)` (a slug value
containing only a single quote and parentheses — no characters Windows or Linux forbid in a
directory name) and called `GET /projects/demo' onmouseover='alert(1)`:

```
200
<h1>Demo</h1><p>review: no flowspec yet</p><p>cases: 0</p>
<a href='/projects/demo' onmouseover='alert(1)/env'>credentials</a> | ...
```

The injected `onmouseover='alert(1)'` attribute is live, unescaped HTML in the response body —
an attribute-injection / XSS hole, exactly the class of defect U5 exists to close. `tests/test_ui.py`
has zero coverage for a slug containing HTML/attribute-breaking characters, so this shipped
without being caught. Filed as `AT-035` (severity: high).

Per the contract's own wording ("Every string derived from user input or project data ...
is passed through `html.escape`") and this skill's hard rule (PASS requires every criterion
evidenced, no partial credit), this criterion is not met as written — the fact that four of five
values in the function are escaped correctly does not satisfy "every."
